# 기시감 (patternscan)

> *이 모양, 전에도 봤다.*

[![CI](https://github.com/zunyob-beep/-/actions/workflows/ci.yml/badge.svg)](https://github.com/zunyob-beep/-/actions/workflows/ci.yml)

지금 1·3·5분봉의 **직전 모양**이 과거에 있었는지 찾고, 그 직후에 실제로 무슨
일이 있었는지 세어서 **단타에 들어갈지 말지**를 판정합니다.

**주문 기능은 없습니다.** 이 프로그램은 시세를 읽고 통계를 낼 뿐입니다.
API 키도 필요 없습니다 (업비트 공개 시세만 씁니다).

```
직전 N개 봉의 모양  →  과거에서 같은 모양 찾기  →  그 직후 1·3·5·10·20봉 결과 집계
                                                            ↓
                                      올랐다 vs 떨어졌다  →  들어갈까 말까
```

---

## ⚠️ 먼저 읽어주세요

- **과거 통계는 미래를 보장하지 않습니다.** 이건 투자 조언이 아닙니다.
- 이 프로그램은 기본적으로 **"들어가지 마세요"**라고 답합니다. 근거가 기준을
  넘겨야만 뒤집힙니다. 무작위 데이터로 시험해 보면 왜 그래야 하는지 알 수 있습니다
  (아래 [왜 이렇게 깐깐한가](#왜-이렇게-깐깐한가) 참고).
- **"올랐다"의 기준은 수수료입니다.** 왕복 비용(수수료+슬리피지)을 넘긴 경우만
  상승으로 셉니다. 0.05% 오른 건 오른 게 아닙니다.

## 어떻게 실행하나

**같은 계산을 두 가지 방법으로 돌릴 수 있습니다.**

| | 웹앱 | 파이썬 |
|---|---|---|
| 어디서 | 브라우저 (아이패드 포함) | PC·맥·라즈베리파이 |
| 계산하는 곳 | **브라우저 안** | 그 컴퓨터의 파이썬 |
| 켜 둘 서버 | 없음 | 있어야 함 |
| 요금 | 0원 | 0원 |
| 받아둔 시세 | 브라우저(IndexedDB) | `data/*.csv` |

두 구현은 **같은 숫자를 냅니다.** 말로 하는 약속이 아니라, 파이썬 결과를
정답지로 뽑아 자바스크립트 결과와 통째로 대조하는 시험이 있습니다
(`tests/js/golden.test.js`). 한쪽만 고치면 그 시험이 깨집니다.

### 웹앱으로 쓰기 (아이패드라면 이쪽)

서버가 없습니다. 시세 받기도, 닮은 과거 찾기도, 이론 채점도 **전부
브라우저 안에서** 일어납니다. 그래서 켜 둘 컴퓨터도, 잠들 코드스페이스도,
쓸 무료분도 없습니다.

**처음 한 번만 준비하면 됩니다.**

1. `github.com/zunyob-beep/-` → **Settings → Pages → Source**를
   **GitHub Actions**로 고릅니다.
2. 여기서 고를 수 없고 *"공개로 바꾸거나 요금제를 올리라"*고 하면, **그때만**
   **Settings → 맨 아래 Change repository visibility → Public**으로 바꾸고
   1번을 다시 합니다.
   *(무료 요금제의 Pages는 공개 저장소에서만 됩니다. 유료 요금제라면 비공개인
   채로 그냥 됩니다. 공개로 바꾸는 건 되돌리기 번거로우니 필요할 때만 하세요 —
   이 저장소에 API 키나 비밀번호는 없습니다.)*
3. **Actions** 탭에서 `웹앱 올리기`가 초록불이 될 때까지 기다립니다 (1~2분).
   빨간불이면 그 화면 맨 위에 **무엇을 눌러야 하는지 한국어로 적혀 있습니다.**
4. 주소가 생깁니다: **`https://zunyob-beep.github.io/-/`**
5. 사파리에서 그 주소를 열고 → 공유 버튼(□↑) → **홈 화면에 추가**

이제 아이콘을 누르면 주소창 없이 앱처럼 뜹니다. 코드를 고쳐 밀어 넣으면
**열려 있던 화면이 스스로 새 판으로 갈아탑니다** (받는 중이면 끝난 뒤에).
화면 오른쪽 위의 판 번호로 지금 무엇이 도는지 확인할 수 있습니다.

> **업비트가 막을 때가 있습니다.** 공개 시세 API의 한도는 초당 10회지만,
> **한도 안이라고 안전한 게 아닙니다.** 초당 5회로도 막혔습니다 — 특히
> **휴대폰 데이터(5G)** 는 한 주소를 여러 사람이 나눠 쓰기 때문에 우리가
> 절반만 써도 남들이 쓴 몫까지 합쳐 넘어갑니다. 그래서 우리는 **초당 3회**만
> 씁니다(봉 받기·맨 위 시세·확인 요청이 전부 이 한 예산을 나눠 씁니다).
> 와이파이에서 하면 훨씬 안정적입니다.
>
> 막히면 화면이 **무엇 때문인지 구분해서** 알려줍니다 — 인터넷이 끊긴 것,
> 업비트에 못 닿는 것, 업비트가 답은 하는데 우리를 거절하는 것.
>
> 마지막 경우에는 **앱이 입을 다뭅니다.** 업비트는 막아 둔 주소로 들어오는
> 요청을 보면 차단을 연장하기 때문에, 두드리지 않는 것 말고는 할 수 있는
> 일이 없습니다. 막힐 때마다 조용히 있는 시간을 1 → 2 → 5 → 10 → 20 → 30분으로
> 늘리고, 그동안은 **한 번도 보내지 않습니다.** 한 번이라도 받아 오면 처음으로
> 되돌립니다. 받아둔 만큼은 그대로 남으므로 잃는 것이 없습니다.
>
> 이건 뒤늦게 고친 것입니다. 예전에는 실패할 때마다 업비트로 3번(요청 1 +
> 진단 2)이 나갔고, 막힌 걸 아는 상태에서도 일단 보내고 실패했습니다. 맨 위
> 시세가 20초마다 도니까 **밤새 1,443번**이 나갔습니다 — 이미 거절당하고 있는
> 주소로. 앱이 스스로 차단을 연장시키고 있었던 셈입니다. 지금은 같은 밤에
> 22번입니다 (`tests/js/upbit.test.js`가 이 8시간을 그대로 돌려서 셉니다).
>
> **결국 원인은 '브라우저에서 직접 부르는 길' 자체였습니다.** 진단표 세 장이
> 같은 말을 했습니다 — no-cors로는 128ms에 닿는데(업비트 서버는 멀쩡히
> 답합니다) 브라우저가 읽을 수 있는 요청은 거의 다 실패합니다. 그리고
> **5G에서 와이파이로 바꿔도 똑같았습니다.** 우리 주소가 차단당한 게 아니라는
> 뜻입니다. 초당 회수를 낮추든 재시도를 늘리든 고칠 수 없는 종류였습니다.
>
> 브라우저가 못 가져오면 **브라우저가 아닌 곳을 거쳐서** 가져오면 됩니다.
> 이제 앱은 직접 길이 세 번 연달아 막히면 **공개 우회 서버로 스스로
> 돌아섭니다.** 직접이 되면 아무 데도 안 거칩니다.
>
> 공개 우회 서버는 사정이 바뀝니다 — corsproxy.io는 유료로 바뀌어
> `401 A valid API key is required`를 돌려주기 시작했습니다. 그런 답이 오면
> 앱이 **다음 우회로 넘어갑니다.** (처음에는 이걸 놓쳐서 거기서 멈췄습니다.
> 401은 '성공한 HTTP 응답'이라, 네트워크 실패에서만 길을 바꾸던 코드가
> 그 갈래를 안 탔습니다.)
>
> **우회 주소를 직접 만들면 더 좋습니다.** 남의 서버를 안 거치고, 한도도
> 온전히 내 몫이 됩니다. 조작부 아래 <b>업비트가 브라우저 요청을 막을 때</b>를
> 펼쳐서 주소를 적으면 그걸 먼저 씁니다. 클라우드플레어 워커로 5분이면
> 만듭니다 — [dash.cloudflare.com](https://dash.cloudflare.com) → Workers →
> Create → 아래 코드를 붙여넣고 Deploy:
>
> ```js
> export default {
>   async fetch(request) {
>     const asked = new URL(request.url).searchParams.get('u');
>     if (!asked || !asked.startsWith('https://api.upbit.com/')) {
>       return new Response('업비트 주소만 받습니다', { status: 400 });
>     }
>     const answer = await fetch(asked, { headers: { accept: 'application/json' } });
>     return new Response(answer.body, {
>       status: answer.status,
>       headers: {
>         'content-type': 'application/json',
>         'access-control-allow-origin': '*',
>       },
>     });
>   },
> };
> ```
>
> 그리고 앱에 `https://내주소.workers.dev/?u={url}` 을 적습니다. `{url}` 자리에
> 업비트 주소가 들어갑니다. 위 코드는 **업비트 주소만** 받아 넘기므로 남이
> 이 워커로 아무 데나 부를 수 없습니다.
>
> 우회 서버가 보는 것은 '어느 종목의 어느 시각'뿐입니다. 계정도 API 키도
> 없고, 받아둔 시세와 계산은 여전히 이 기기 안에만 있습니다.
>
> **막힌 날에는 짧은 기간부터 누르세요.** 7일치는 요청이 51번, 1일치는
> 8번이라 30일치(216번)가 못 끝내는 상황에서도 통과합니다. 한 번 받은
> 과거는 다시 안 받으므로 7일 → 30일 → 90일로 올려 가며 눌러도 받는
> 총량은 같습니다.

**웹앱에서 알아두면 좋은 것**

- **지나간 봉은 다시 받지 않습니다.** 처음 30일치를 받을 때는 200개씩
  216번 요청해 1분쯤 걸리지만, **두 번째부터는 1번**입니다. (실측값입니다 —
  `tests/js/browser.mjs`가 매번 이 횟수를 셉니다.)
- **1분봉만 받습니다.** 업비트의 3분봉은 1분봉 셋을 묶은 것과 정확히 같고,
  5분봉은 다섯을 묶은 것과 같습니다. 이미 받은 걸로 만들 수 있는 것을 다시
  받을 이유가 없어서, 요청이 331번에서 216번으로 줄었습니다. 묶는 데 드는
  시간은 4년치에서도 50밀리초입니다.
- **기간은 4년까지입니다.** 감으로 정하지 않고 실제로 재 봤습니다.

  | 고르면 | 1분봉 | 요청 | 계산 시간 | 처음 받는 시간 |
  |---|---|---|---|---|
  | 1일 | 1,440개 | 8번 | 0.01초 | 3초 |
  | **7일**(기본) | **10,080개** | **51번** | **0.03초** | **17초** |
  | 30일 | 43,200개 | 216번 | 0.1초 | 1분 |
  | 90일 | 129,600개 | 648번 | 0.2초 | 4분 |
  | 1년 | 525,600개 | 2,628번 | 0.7초 | 15분 |
  | 2년 | 1,051,200개 | 5,256번 | 1.4초 | 29분 |
  | 4년 | 2,102,400개 | 10,512번 | 2.8초 | 58분 |

  받는 시간은 **한 번도 안 막혔을 때**입니다. 중간에 막히면 기다렸다 이어
  받으므로 실제로는 더 걸릴 수 있습니다. 긴 기간은 와이파이에서 하세요.

  처음 골라져 있는 것은 **7일**입니다. 1일치는 17초가 아니라 3초면 끝나지만
  닮은 과거가 스무 개도 안 나와서 "표본이 모자랍니다"만 보게 됩니다.
  7일은 통계가 나오면서도 막힌 날에 통과할 만큼 짧습니다.

  계산은 워커에서 도니 그동안에도 화면은 안 멈춥니다. 받는 건 오래 걸리지만
  **중간에 멈춰도 받은 만큼 남고, 다시 누르면 이어서** 받습니다.

  8년(420만 봉)은 두지 않았습니다 — 숫자 배열만 270MB가 넘어 아이패드
  사파리가 탭을 죽이는 쪽에 가깝습니다. 4년도 155MB라 상한선에 가깝습니다. 그보다 긴 과거가 필요하면 파이썬
  판에 8년이 그대로 있습니다.
- 받아둔 시세는 **그 기기의 브라우저 안에만** 있습니다. 아이패드에서 받은
  것과 PC에서 받은 것은 따로입니다. 어디로도 보내지 않습니다.
- 인터넷이 없어도 앱은 뜨고, **받아둔 시세로 다시 계산**은 그대로 됩니다.
- 시세를 지우려면 '받아둔 시세'나 '무엇으로 계산했나' 칸의
  **받아둔 시세 지우기**를 누르세요.
- 잘 안 될 때는 **업비트 연결 진단**을 누르면 여덟 가지를 하나씩 물어보고
  무엇이 문제인지 한국어로 결론까지 말해 줍니다.

### 파이썬으로 쓰기

**파이썬 3.10 이상이 도는 곳이면 어디서든 됩니다.** 필요한 것은
`requests`와 `numpy` 둘뿐이고, 시세는 업비트 공개 API에서 받아 `data/`
폴더에 CSV로 쌓습니다. 계정도 API 키도 없습니다.

| 어디서 | 장점 | 걸리는 점 |
|---|---|---|
| **집 PC·맥** | 빠르고 공짜, 데이터가 내 컴퓨터에 | 그 컴퓨터가 켜져 있어야 |
| **GitHub Codespaces** | 아이패드만 있어도 됨 | 무료분이 정해져 있음 (아래 참고) |
| **라즈베리파이·NAS·VPS** | 24시간 켜둘 수 있음 | 직접 준비해야 |
| **회사·학교 컴퓨터** | — | 업비트가 막혀 있을 수 있음 (`doctor`로 확인) |

### PC·맥이 있다면 (가장 쉽습니다)

```bash
git clone https://github.com/zunyob-beep/-
cd ./-        # 저장소 이름이 '-'입니다. `cd -`는 '이전 폴더로'라는 뜻이라 안 됩니다
./start.sh                    # 맥·리눅스
start.bat                     # 윈도우 (더블클릭해도 됩니다)
```

파이썬 환경을 만들고, 업비트 시세를 받고, 브라우저를 여는 것까지 한 번에 합니다.
두 번째부터는 **새로 생긴 봉만** 이어 받으므로 몇 초면 뜹니다.

아이패드·휴대폰에서 **같은 와이파이로** 보시려면 `./start.sh --lan`
(윈도우는 `start.bat --lan`). 접속할 주소를 화면에 찍어 줍니다.

더 긴 과거로 보고 싶으면:

```bash
COUNT=4204800 ./start.sh      # 1분봉 8년치 (처음 한 번 40분쯤)
```

중간에 끊겨도 받은 만큼 저장되니, 다시 실행하면 이어서 받습니다.

### 아이패드·폰밖에 없다면 (GitHub Codespaces)

터미널이 없는 기기에서도 브라우저만으로 돌릴 수 있습니다.
**명령어는 한 줄도 칠 필요 없습니다.**

1. 사파리에서 `github.com/zunyob-beep/-` 에 들어가 로그인합니다
2. 파일 목록 위 초록색 **`< > Code`** 버튼을 누릅니다
3. **Codespaces** 탭 → **Create codespace on main**
4. 검은 화면에 글자가 쭉 올라갑니다. **2~3분 기다립니다**

기다리는 동안 컨테이너가 파이썬을 깔고, 다 되면 **화면이 저절로 뜹니다**
(`postStartCommand`가 `ui`를 자동으로 띄웁니다).

미리보기가 안 뜨면 아래쪽 **PORTS** 탭 → 8765 줄의 지구본 아이콘을 누르세요.

5. 화면에서 **`얼마나 과거까지`** 를 고르고 **`지금 시세로 판단받기`** 를 누릅니다 —
   시세 받기부터 계산까지 버튼 하나로 다 합니다

   | 고르면 | 1분봉 | 처음 받는 시간 |
   |---|---|---|
   | 7일 | 10,080개 | 금방 |
   | 30일 | 43,200개 | 1분쯤 |
   | 90일 | 129,600개 | 몇 분 |

> **무료분을 아끼려면.** Codespaces는 접속이 끊겨야 잠듭니다. 이 화면은
> 탭이 안 보이면 서버에 아무것도 묻지 않으므로, **다른 탭으로 넘어가거나
> 홈 화면으로 나가면** 30분 뒤 저절로 잠듭니다. 다 봤으면 탭을 닫는 게
> 가장 확실합니다. 남은 무료분은 github.com/settings/billing 에서 봅니다.
> 기본 지출 한도가 0원이라, 무료분을 다 써도 **자동으로 결제되지 않고
> 그냥 멈춥니다.**
>
> **업비트가 막혀 있을 수도 있습니다.** Codespaces는 마이크로소프트
> 클라우드에서 돌아가고, 거기서 업비트에 닿는지는 계정·지역에 따라
> 다릅니다. 안 되면 터미널에서 `python -m patternscan doctor` 를 쳐서
> 확인하세요. 막혀 있으면 PC에서 받은 `data/*.csv`를 끌어다 놓으면 됩니다.

### 앱처럼 홈 화면에 두기

화면이 뜬 상태에서 홈 화면에 얹으면, 주소창 없이 아이콘으로 바로 열립니다.

**어떤 주소를 추가해야 하는지는 서버가 시작할 때 찍어 줍니다.**

```
  아이패드·폰의 홈 화면에 추가할 주소:
    http://192.168.0.7:8765/
    공유기가 이 컴퓨터에 다른 IP를 주면 이 주소는 바뀝니다 —
    아이콘이 안 열리면 여기 찍힌 새 주소로 다시 추가하세요.
```

`127.0.0.1`은 넣으면 안 됩니다 — '이 기기 자신'이라는 뜻이라,
아이패드에 넣으면 아이패드를 가리킵니다.

| 기기 | 방법 |
|---|---|
| 아이패드·아이폰 (사파리) | 공유 버튼(□↑) → **홈 화면에 추가** |
| 안드로이드 (크롬) | 화면에 뜨는 **홈 화면에 추가** 버튼, 또는 ⋮ → 앱 설치 |
| PC (크롬·엣지) | 주소창 오른쪽 설치 아이콘 |

**계산은 여전히 컴퓨터의 파이썬이 합니다.** 아이콘은 그 화면으로 가는
지름길일 뿐, 서버가 꺼져 있으면 결과가 나오지 않습니다. 그래서 서버에
닿지 않으면 앱이 흰 화면 대신 **무엇을 하면 되는지** 적힌 안내를 띄웁니다.

<details>
<summary>기술적으로는</summary>

서비스 워커는 **보안 컨텍스트에서만** 등록됩니다. `localhost`와 https는
되고, 같은 와이파이의 `http://192.168.x.x`는 안 됩니다. LAN 주소에서도
홈 화면 추가와 전체 화면은 되지만(iOS는 meta 태그만 봅니다), 서버가
꺼졌을 때 대신 띄울 화면이 캐시에 없습니다. Codespaces는 https로
넘겨주므로 전부 동작합니다.

서비스 워커는 **`/api/*`를 절대 캐시하지 않습니다.** 3시간 전 가격을
지금 가격이라고 보여주느니 실패하는 편이 낫기 때문입니다. 나머지도
항상 네트워크를 먼저 보고, 캐시는 네트워크가 죽었을 때만 씁니다.

아이콘은 `tools/make_icons.py`가 그립니다 (`python tools/make_icons.py`).
</details>

### 2. 확률만 보기 (권장)

```bash
python -m patternscan odds
```

**판단을 내리지 않고 사실만 보여줍니다.** 지금 모양과 닮은 과거를 찾아,
그 뒤에 무슨 일이 있었는지 셉니다.

```
  ■ 1분봉 — 직전 180개와 닮은 과거 구간 100개 (유사도 0.95 이상)
                 올라 있을 확률        평소      차이      수수료까지 넘길 확률      평소
     ──────────────────────────────────────────────────────────────────
       10분          56%       50%     +6%              29%       22%
         (100개 중 56개)   불확실 범위 46%~66%  (평소와 구분 안 됨)
```

**"56%"는 혼자 나오지 않습니다.** 반드시 셋이 함께 나옵니다:

| | 왜 필요한가 |
|---|---|
| **평소** | 평소가 55%면 56%는 아무 의미가 없습니다 |
| **불확실 범위** | 표본이 적으면 확률이 흔들립니다 |
| **수수료까지 넘길 확률** | 오르기만 해서는 돈이 안 됩니다 |

불확실 범위가 '평소'를 품고 있으면 **(평소와 구분 안 됨)**이 붙습니다 —
그 숫자는 우연과 구분되지 않는다는 뜻입니다.

```
  종목 KRW-BTC · 왕복 비용 0.140%

    5분봉: 봉 8,640개

==================================================================
  🔴 들어가지 마세요 — 근거가 기준에 못 미칩니다.

    · 55개 조합을 뒤졌다는 점을 보정하면 우연과 충분히 구분되지 않습니다.

    · 지금은 들어갈 근거가 없습니다.

  조합                               표본      승률      기준      초과       평균     유사도      q값
  ────────────────────────────────────────────────────────────────────────
  3분봉 5개 → 20봉                     60   55.0%   37.6%  +17.4%  +0.118%    0.98   0.411
  1분봉 20개 → 5봉                     37   32.4%   21.1%  +11.3%  +0.061%    0.85   1.000
  ...
```

읽는 법:

| 칸 | 뜻 |
|---|---|
| **표본** | 과거에서 찾은 같은 모양의 개수 |
| **승률** | 그중 왕복 비용을 넘겨 오른 비율 (보합은 실패로 셈) |
| **기준** | 같은 자리에서 시점만 옮겼을 때의 상승 비율 — 비교 대상 |
| **초과** | 승률 − 기준. **이게 0 근처면 이 모양에는 정보가 없습니다** |
| **평균** | 평균 수익률. 왕복 비용보다 커야 실제로 돈이 됩니다 |
| **유사도** | 표본 중 가장 덜 닮은 모양의 상관계수 (1.00=완전히 같음) |
| **직선성** | 질의 모양이 직선에 얼마나 가까운지. 0.75 이상이면 `~`로 표시하고, '모양'이 아니라 '추세'를 본 것으로 봅니다 |
| **q값** | 285개 조합을 뒤졌다는 걸 보정한 뒤의 유의확률 |

옵션:

```bash
python -m patternscan scan --detail              # 상위 조합 상세
python -m patternscan scan --similarity 0.9      # 더 엄격하게 (표본은 줄어듦)
python -m patternscan scan --fee 0.0005          # 수수료 조정
python -m patternscan scan --scale amplitude     # 변동폭까지 같아야 같은 모양
python -m patternscan scan --refresh             # 시세 새로 받고 판정
```

### 4. 어느 길이가 실제로 잘 맞았는지 재기

```bash
python -m patternscan validate
```

**과거 여러 시점으로 돌아가서**, 그 시점까지의 데이터만 보고 예측을 낸 뒤
실제로 무슨 일이 있었는지 맞춰봅니다. `scan`이 "지금 들어갈까"를 답한다면
`validate`는 **"그 답을 믿어도 되는가"**를 답합니다.

```
   길이   지평    예측   적중률     찍기     실력    오차     부호  상승예측 평균   전체 평균
  ────────────────────────────────────────────────────────────────────────────
     20     3     396   63.0%   46.9%  +16.1%  ±2.5%   61.2%     +0.9373%   +0.0980% ←
```

읽는 법 — **적중률만 보면 반드시 속습니다.**

| 칸 | 뜻 |
|---|---|
| **찍기** | 항상 다수 쪽으로만 찍었을 때의 적중률 |
| **실력** | 적중률 − 찍기. 0 이하면 그냥 찍는 것만 못합니다 |
| **오차** | 실력의 표준오차. **예측 150회면 ±4%라, 실력이 없어도 ±8%는 그냥 나옵니다** |
| **상승예측 평균** | '상승'이라 했을 때의 실제 평균 수익. 왕복 비용을 넘어야 돈이 됩니다 |

1분 뒤에 수수료를 넘겨 오르는 경우는 원래 20%도 안 됩니다. 그러니 무조건
"안 오른다"고 찍기만 해도 **적중률 80%**가 나옵니다. 그래서 찍기와 나란히 둡니다.

```bash
python -m patternscan validate --points 2000              # 더 많은 시점으로
python -m patternscan validate --lengths 5,10,20,40       # 특정 길이만
python -m patternscan validate --timeframe minute5        # 5분봉으로
python -m patternscan validate --buckets 5                # 구간별로 잘라 비교
```

#### '구간별로 자르기' 방식 (`--buckets`)

모양을 연속된 숫자로 비교하는 대신, 각 봉을 **급등/상승/보합/하락/급락** 같은
구간으로 잘라 기호가 같은지로 비교합니다.

```
연속:  [-0.31, +1.42, +0.05, -0.88, +1.21]   → 상관계수로 비교
기호:  [  0,     4,     2,     1,     4  ]   → 5칸 중 몇 칸 맞는지로 비교
```

경계는 **창 안의 표준편차로 나눈 뒤** 정규분포 분위수로 잡습니다. 고정 퍼센트
(예: ±0.1%)를 안 쓰는 이유는 비트코인 변동성이 시기마다 크게 다르기 때문입니다 —
2022년 하락장의 0.1%와 조용한 구간의 0.1%는 전혀 다른 사건입니다.

**실측 결과, 연속 방식보다 낫지 않았습니다.** 실제 BTC 40만 봉으로 재보면:

| 방식 | 최고 실력 | 상승예측 평균수익 |
|---|---|---|
| 연속 (상관계수 0.85) | −28.6% | −0.011% |
| 기호 3구간 | −20.4% | +0.005% |
| 기호 5구간 | −30.5% | −0.013% |
| 기호 9구간 | −29.6% | −0.012% |

전부 실력이 음수라 어느 쪽도 쓸 수 없습니다. 기호 3구간이 그나마 덜 나쁘지만
왕복 비용 0.140%에는 한참 못 미칩니다.

### 5. 다른 데서 구한 데이터 쓰기

업비트는 2017년 10월 개장이라 그 이전이 없습니다. 더 긴 과거로 검증하고
싶으면 공개된 OHLCV CSV를 들여올 수 있습니다.

```bash
python -m patternscan import btcusd_1-min.csv --market BTC-USD --resample
python -m patternscan validate --market BTC-USD
```

`--resample`을 주면 1분봉에서 3분봉·5분봉도 같이 만듭니다. 시계에 맞춰
자르고(3분봉은 0·3·6분 시작), **1분봉이 3개 다 있는 구간만** 3분봉으로
만듭니다 — 2개로 만들면 없던 봉을 지어내는 것이니까요.

> ⚠️ **서로 다른 거래소 데이터를 이어 붙이지 마세요.** 거래소가 다르면
> 통화도 유동성도 프리미엄도 다릅니다. 이어 붙이면 이음매에서 없던 모양이
> 생기고, 그 자리가 '과거에 있던 모양'으로 잡힙니다.
> 비교하고 싶으면 **따로 들여와 따로 돌려서 결과를 맞춰보세요.**
> 서로 다른 거래소에서 같은 N이 이긴다면 그게 훨씬 강한 근거입니다.

### 6. 화면으로 보기

```bash
python -m patternscan ui
```

브라우저에서 `http://127.0.0.1:8765` 가 열립니다. **확률 표**가 중심이고,
행을 누르면 그 조합의 **실제 사례**가 그려집니다 — 올랐던 사례 3개와 떨어졌던 사례 3개.

각 사례는 **그 당시 모양(회색)과 지금 모양(파랑)을 겹쳐서** 보여주므로,
"정말 닮았나"를 숫자가 아니라 눈으로 확인할 수 있습니다. 오른쪽 작은 그림은
그 직후에 실제로 어떻게 움직였는지입니다.

**가장 많이 오른 사례가 아니라 가장 닮은 사례**를 고릅니다 — 많이 오른 것만
보여주면 실제보다 좋아 보이니까요.

서버는 기본적으로 `127.0.0.1`에만 붙습니다 — 이 컴퓨터에서만 열립니다.

아이패드나 휴대폰에서 보시려면:

```bash
python -m patternscan ui --host 0.0.0.0
```

같은 와이파이에서 접속할 주소를 화면에 찍어 줍니다. 인터넷에 공개되지는 않지만
**같은 와이파이의 누구나 볼 수 있으니** 카페·공용 와이파이에서는 쓰지 마세요.

전부 곱하면 **285개 조합**을 한 번에 봅니다. 이게 이 프로그램의 가장 큰 위험이기도 합니다
(아래).

### '같은 모양'이란

가격을 그대로 비교하면 4,000만원 구간과 9,000만원 구간은 아무리 모양이 같아도
겹치지 않습니다. 그래서 두 단계로 정규화합니다.

1. **첫 봉 대비 수익률 경로**로 바꾼다 → 가격대 무관
2. **표준편차로 나눈다** → 변동폭 무관, 오르내린 '모양'만 남음

2단계를 거치면 두 경로 사이의 거리와 상관계수가 정확히 이렇게 연결됩니다.

```
거리² = 2 × (1 − 상관계수)
```

그래서 유사도를 상관계수로 말할 수 있습니다. `--scale amplitude`를 주면 2단계를
건너뛰어 변동폭까지 같아야 '같은 모양'으로 봅니다.

## 왜 이렇게 깐깐한가

만드는 동안 **순수한 무작위 데이터에서 "들어가라 — 승률 61.4%"가 나왔습니다.**
90개 조합 중 28개가 "통계적으로 유의"했고 q값은 0.001이었습니다. 전부 허깨비였습니다.

원인은 넷이었고, 넷 다 막았습니다.

**1. 이항검정을 쓰고 있었다.**
이항검정은 매치들이 서로 독립인 동전 던지기라고 가정합니다. 그런데 비슷한 모양은
시간적으로 뭉쳐서 나타납니다(변동성이 비슷한 구간끼리 닮으니까). 그 구간이 마침
오르는 국면이었다면 승률이 다 같이 높아집니다 — 모양이 예측력을 가져서가 아니라
같은 국면에서 뽑혔기 때문에.

→ **순열검정**으로 바꿨습니다. 매치 위치는 그대로 두고 시점만 통째로 옮겨서,
뭉침 구조와 자기상관은 유지한 채 '이 모양 다음에 올랐다'는 연결만 끊습니다.

**2. '같은 모양'을 강제하지 않았다** (가장 컸습니다).
거리 임계값이 없어서 거리 1.78짜리 구간까지 표본에 들어오고 있었습니다.
그런데 **거리 1.41이 이미 상관계수 0**, 즉 아무 관계 없는 모양입니다. 1.78은
상관이 오히려 음수 — 정반대 모양을 "같은 모양"이라며 세고 있었던 겁니다.

→ **유사도 하한 0.85**를 뒀습니다. 이거 하나로 무작위 데이터의 거짓 신호가
20개 시드 중 1개에서 **0개**가 됐습니다.

**3. 한쪽 국면에서만 성립하는 걸 걸러내지 않았다.**
→ 매치를 **시간순으로 반 갈라** 양쪽 모두에서 기준을 넘겨야 인정합니다.

**4. 285번 뒤졌다는 사실을 반영하지 않았다.**
아무 정보가 없는 데이터에서도 285번 중 p<0.05인 조합이 평균 14개 나옵니다.
→ **Benjamini-Hochberg** 보정을 하고, 진입 판정에는 q ≤ 0.02를 요구합니다.

여기에 더해 **평균 수익이 왕복 비용을 넘어야** 하고, **통과 조합이 2개 이상**이어야
합니다. 승률이 높아도 이기는 폭이 작으면 수수료로 다 나가고, 110개 중 하나만
아슬아슬하게 켜진 건 우연에 가깝습니다.

이 여섯 가지를 **모두** 통과해야 "들어갈 만합니다"가 나옵니다.

### 그리고 그 반대 방향의 버그도 있었다

위 장치들을 다 넣고 나니 무작위 데이터에서 진입 신호가 0/20이 됐습니다.
그런데 **비용의 10배가 확정으로 오르는 신호를 심어놓고 돌려보니 그것도 0/10으로
놓쳤습니다.**

순열 시행이 400회여서 p값의 최솟값이 1/401 = 0.0025로 막혀 있었던 게 원인이었습니다.
진입에는 q ≤ 0.02가 필요하고 q = p × 조합수 / 순위이므로, 조합이 90개면 1등이라도
q = 0.0025 × 90 ≈ **0.22**. 즉 **어떤 데이터로도 진입 신호가 나올 수 없는 상태**였습니다.

잡음에 안전했던 게 아니라 아예 잠겨 있었던 것이고, 무작위 데이터 시험은 전부
통과했기 때문에 티가 나지 않았습니다.

→ 이 귀무분포는 **오프셋 하나로만 결정**되므로 가짓수가 유한합니다. 표본추출할
이유가 없어서 **전수로 계산**하도록 바꿨습니다. 해상도가 봉 개수분의 1이 되면서
바닥이 사라졌고, 검출이 **0/10 → 10/10**이 됐습니다.

## 왜 180까지인가

더 늘려도 얻는 게 없고, 오히려 오해를 부릅니다. 1분봉 43,200개에서 질의 위치
30곳을 훑어 재보면:

| 길이 | 표본 20개 이상 나온 비율 | 표본 중앙값 |
|---|---|---|
| 5 | 97% | 60 |
| 20 | 57% | 34 |
| 60 | 27% | 1 |
| 120 | 23% | 2 |
| **180** | **20%** | **0** |
| 240 | 10% | 0 |
| 300 | 10% | 1 |
| 400 | 3% | 0 |

180에서 이미 다섯 번에 한 번만 표본이 찹니다. 240 이상은 열 번에 한 번,
400은 서른 번에 한 번입니다. 겹치지 않게 놓을 수 있는 최대 개수 자체가
줄어들기 때문입니다 (길이 600이면 1분봉 30일치에 최대 72개, 5분봉이면 14개라
표본 20개가 **원천적으로 불가능**합니다).

### 더 중요한 이유: 긴 창에서 표본이 나오면 그건 대개 직선입니다

긴 모양이 과거에 자주 반복될 리 없습니다. 그런데도 표본이 넉넉히 나온다면
모양이 단순해서입니다. 질의 위치 40곳의 직선성(직선 적합 R²) 중앙값:

| 길이 | 표본 20개 이상일 때 | 표본이 적을 때 |
|---|---|---|
| 60 | 0.72 | 0.25 |
| 120 | 0.72 | 0.38 |
| 180 | 0.80 | 0.40 |
| 240 | 0.83 | 0.22 |
| 300 | **0.88** | 0.22 |

길이 300에서 표본이 20개 넘게 나오면 그 '모양'은 88%가 직선으로 설명됩니다.
즉 "특이한 모양이 반복됐다"가 아니라 **"같은 방향으로 추세 중"**을 센 겁니다.

막지는 않습니다 — 추세를 타는 것도 근거는 근거입니다. 대신 **직선성을 같이
보여주고**, 0.75를 넘으면 표에 `~`를 붙이고 판정문에도 명시합니다. 사용자가
"직전 180개 모양이 과거에 25번 있었다"로 오해하지 않도록.

## 셈할 때 지키는 규칙

- **미래를 안 본다.** 후보 구간은 질의 구간이 시작하기 *전에* 끝나야 하고, 결과를
  관측할 h봉까지도 질의 구간 시작 전에 끝나야 합니다.
- **겹치면 안 센다.** 한 칸씩 밀린 구간들은 사실상 같은 구간입니다. 다 세면
  표본 30개가 실제로는 1개인데 30개인 척하게 됩니다.
- **끊긴 구간은 버린다.** 업비트는 거래가 없는 분의 봉을 주지 않습니다. 그 자리를
  이어 붙이면 실제로는 떨어진 두 시점이 연속된 모양으로 보입니다.
- **평평한 구간은 버린다.** 안 움직인 창끼리는 거리가 0이라 전부 '완벽한 매치'가
  됩니다.
- **보합은 실패로 센다.** 분모에 남깁니다. 안 그러면 승률이 부풀려집니다.

각각에 대응하는 시험이 `tests/test_scan.py`에 있습니다.

> `tools/goldens.py`가 파이썬 결과를 JSON으로 뽑아 두고
> `tests/js/golden.test.js`가 같은 입력에 같은 숫자가 나오는지 통째로
> 대조합니다. RSI 임계값을 70에서 71로 한 칸만 옮겨도 이 시험이 깨집니다.

읽는 순서를 하나만 고른다면 `shape.py` → `scan.py` → `stats.py`입니다.
'같은 모양'의 정의에서 시작해 판정까지 이어집니다.

**넷 다 CI에서 돌고, 하나라도 깨지면 배포가 안 됩니다.** 여태 CI는 계산만

시험은 네트워크를 타지 않습니다. 업비트 장애나 레이트 리밋에 CI가 흔들리면
