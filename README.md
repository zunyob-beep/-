# 모양 찾기 (patternscan)

[![CI](https://github.com/zunyob-beep/-/actions/workflows/ci.yml/badge.svg)](https://github.com/zunyob-beep/-/actions/workflows/ci.yml)

지금 1·3·5분봉의 **직전 모양**이 과거에 있었는지 찾고, 그 직후에 실제로 무슨
일이 있었는지 세어서 **단타에 들어갈지 말지**를 판정합니다.

**주문 기능은 없습니다.** 이 프로그램은 시세를 읽고 통계를 낼 뿐입니다.
API 키도 필요 없습니다 (업비트 공개 시세만 씁니다).

```
직전 N개 봉의 모양  →  과거에서 같은 모양 찾기  →  그 직후 1·3·5·10·20봉 결과 집계
                                                            ↓
                                      올랐다 vs 떨어졌다  →  들어갈까 말까
```

---

## ⚠️ 먼저 읽어주세요

- **과거 통계는 미래를 보장하지 않습니다.** 이건 투자 조언이 아닙니다.
- 이 프로그램은 기본적으로 **"들어가지 마세요"**라고 답합니다. 근거가 기준을
  넘겨야만 뒤집힙니다. 무작위 데이터로 시험해 보면 왜 그래야 하는지 알 수 있습니다
  (아래 [왜 이렇게 깐깐한가](#왜-이렇게-깐깐한가) 참고).
- **"올랐다"의 기준은 수수료입니다.** 왕복 비용(수수료+슬리피지)을 넘긴 경우만
  상승으로 셉니다. 0.05% 오른 건 오른 게 아닙니다.

## 쓰는 법

### 1. 시세 받기 (처음 한 번, 몇 분 걸립니다)

```bash
python -m patternscan fetch
```

1분봉 30일치(43,200개)와 그에 맞는 3분봉·5분봉을 받아 `data/`에 CSV로 저장합니다.
업비트는 한 번에 200개씩만 주므로 216번 요청합니다. 다음부터는 캐시를 씁니다.

```bash
python -m patternscan fetch --market KRW-ETH        # 다른 종목
python -m patternscan fetch --count 86400           # 1분봉 60일치
python -m patternscan fetch --refresh               # 캐시 무시하고 새로
```

### 2. 판정하기

```bash
python -m patternscan scan
```

```
  종목 KRW-BTC · 왕복 비용 0.140%
  '같은 모양' 기준: 상관계수 0.85 이상
    1분봉: 봉 43,200개
    3분봉: 봉 14,400개
    5분봉: 봉 8,640개

==================================================================
  🔴 들어가지 마세요 — 근거가 기준에 못 미칩니다.
==================================================================
    · 가장 나은 조합: 3분봉 직전 5개 → 20봉 뒤, 초과 승률 +17.4% (표본 60건, q=0.411)
    · 55개 조합을 뒤졌다는 점을 보정하면 우연과 충분히 구분되지 않습니다.
    · 평균 수익 +0.118%가 왕복 비용 0.140%를 넘지 못합니다 — 승률이 높아도 수수료로 나갑니다.
    · 지금은 들어갈 근거가 없습니다.

  조합                               표본      승률      기준      초과       평균     유사도      q값
  ────────────────────────────────────────────────────────────────────────
  3분봉 5개 → 20봉                     60   55.0%   37.6%  +17.4%  +0.118%    0.98   0.411
  1분봉 20개 → 5봉                     37   32.4%   21.1%  +11.3%  +0.061%    0.85   1.000
  ...
```

읽는 법:

| 칸 | 뜻 |
|---|---|
| **표본** | 과거에서 찾은 같은 모양의 개수 |
| **승률** | 그중 왕복 비용을 넘겨 오른 비율 (보합은 실패로 셈) |
| **기준** | 같은 자리에서 시점만 옮겼을 때의 상승 비율 — 비교 대상 |
| **초과** | 승률 − 기준. **이게 0 근처면 이 모양에는 정보가 없습니다** |
| **평균** | 평균 수익률. 왕복 비용보다 커야 실제로 돈이 됩니다 |
| **유사도** | 표본 중 가장 덜 닮은 모양의 상관계수 (1.00=완전히 같음) |
| **직선성** | 질의 모양이 직선에 얼마나 가까운지. 0.75 이상이면 `~`로 표시하고, '모양'이 아니라 '추세'를 본 것으로 봅니다 |
| **q값** | 285개 조합을 뒤졌다는 걸 보정한 뒤의 유의확률 |

옵션:

```bash
python -m patternscan scan --detail              # 상위 조합 상세
python -m patternscan scan --similarity 0.9      # 더 엄격하게 (표본은 줄어듦)
python -m patternscan scan --fee 0.0005          # 수수료 조정
python -m patternscan scan --scale amplitude     # 변동폭까지 같아야 같은 모양
python -m patternscan scan --refresh             # 시세 새로 받고 판정
```

### 3. 어느 길이가 실제로 잘 맞았는지 재기

```bash
python -m patternscan validate
```

**과거 여러 시점으로 돌아가서**, 그 시점까지의 데이터만 보고 예측을 낸 뒤
실제로 무슨 일이 있었는지 맞춰봅니다. `scan`이 "지금 들어갈까"를 답한다면
`validate`는 **"그 답을 믿어도 되는가"**를 답합니다.

```
   길이   지평    예측   적중률     찍기     실력    오차     부호  상승예측 평균   전체 평균
  ────────────────────────────────────────────────────────────────────────────
     20     3     396   63.0%   46.9%  +16.1%  ±2.5%   61.2%     +0.9373%   +0.0980% ←
```

읽는 법 — **적중률만 보면 반드시 속습니다.**

| 칸 | 뜻 |
|---|---|
| **찍기** | 항상 다수 쪽으로만 찍었을 때의 적중률 |
| **실력** | 적중률 − 찍기. 0 이하면 그냥 찍는 것만 못합니다 |
| **오차** | 실력의 표준오차. **예측 150회면 ±4%라, 실력이 없어도 ±8%는 그냥 나옵니다** |
| **상승예측 평균** | '상승'이라 했을 때의 실제 평균 수익. 왕복 비용을 넘어야 돈이 됩니다 |

1분 뒤에 수수료를 넘겨 오르는 경우는 원래 20%도 안 됩니다. 그러니 무조건
"안 오른다"고 찍기만 해도 **적중률 80%**가 나옵니다. 그래서 찍기와 나란히 둡니다.

```bash
python -m patternscan validate --points 2000              # 더 많은 시점으로
python -m patternscan validate --lengths 5,10,20,40       # 특정 길이만
python -m patternscan validate --timeframe minute5        # 5분봉으로
```

전부 곱하면 **285개 조합**을 한 번에 봅니다. 이게 이 프로그램의 가장 큰 위험이기도 합니다
(아래).

### '같은 모양'이란

가격을 그대로 비교하면 4,000만원 구간과 9,000만원 구간은 아무리 모양이 같아도
겹치지 않습니다. 그래서 두 단계로 정규화합니다.

1. **첫 봉 대비 수익률 경로**로 바꾼다 → 가격대 무관
2. **표준편차로 나눈다** → 변동폭 무관, 오르내린 '모양'만 남음

2단계를 거치면 두 경로 사이의 거리와 상관계수가 정확히 이렇게 연결됩니다.

```
거리² = 2 × (1 − 상관계수)
```

그래서 유사도를 상관계수로 말할 수 있습니다. `--scale amplitude`를 주면 2단계를
건너뛰어 변동폭까지 같아야 '같은 모양'으로 봅니다.

## 왜 이렇게 깐깐한가

만드는 동안 **순수한 무작위 데이터에서 "들어가라 — 승률 61.4%"가 나왔습니다.**
90개 조합 중 28개가 "통계적으로 유의"했고 q값은 0.001이었습니다. 전부 허깨비였습니다.

원인은 넷이었고, 넷 다 막았습니다.

**1. 이항검정을 쓰고 있었다.**
이항검정은 매치들이 서로 독립인 동전 던지기라고 가정합니다. 그런데 비슷한 모양은
시간적으로 뭉쳐서 나타납니다(변동성이 비슷한 구간끼리 닮으니까). 그 구간이 마침
오르는 국면이었다면 승률이 다 같이 높아집니다 — 모양이 예측력을 가져서가 아니라
같은 국면에서 뽑혔기 때문에.

→ **순열검정**으로 바꿨습니다. 매치 위치는 그대로 두고 시점만 통째로 옮겨서,
뭉침 구조와 자기상관은 유지한 채 '이 모양 다음에 올랐다'는 연결만 끊습니다.

**2. '같은 모양'을 강제하지 않았다** (가장 컸습니다).
거리 임계값이 없어서 거리 1.78짜리 구간까지 표본에 들어오고 있었습니다.
그런데 **거리 1.41이 이미 상관계수 0**, 즉 아무 관계 없는 모양입니다. 1.78은
상관이 오히려 음수 — 정반대 모양을 "같은 모양"이라며 세고 있었던 겁니다.

→ **유사도 하한 0.85**를 뒀습니다. 이거 하나로 무작위 데이터의 거짓 신호가
20개 시드 중 1개에서 **0개**가 됐습니다.

**3. 한쪽 국면에서만 성립하는 걸 걸러내지 않았다.**
→ 매치를 **시간순으로 반 갈라** 양쪽 모두에서 기준을 넘겨야 인정합니다.

**4. 285번 뒤졌다는 사실을 반영하지 않았다.**
아무 정보가 없는 데이터에서도 285번 중 p<0.05인 조합이 평균 14개 나옵니다.
→ **Benjamini-Hochberg** 보정을 하고, 진입 판정에는 q ≤ 0.02를 요구합니다.

여기에 더해 **평균 수익이 왕복 비용을 넘어야** 하고, **통과 조합이 2개 이상**이어야
합니다. 승률이 높아도 이기는 폭이 작으면 수수료로 다 나가고, 110개 중 하나만
아슬아슬하게 켜진 건 우연에 가깝습니다.

이 여섯 가지를 **모두** 통과해야 "들어갈 만합니다"가 나옵니다.

### 그리고 그 반대 방향의 버그도 있었다

위 장치들을 다 넣고 나니 무작위 데이터에서 진입 신호가 0/20이 됐습니다.
그런데 **비용의 10배가 확정으로 오르는 신호를 심어놓고 돌려보니 그것도 0/10으로
놓쳤습니다.**

순열 시행이 400회여서 p값의 최솟값이 1/401 = 0.0025로 막혀 있었던 게 원인이었습니다.
진입에는 q ≤ 0.02가 필요하고 q = p × 조합수 / 순위이므로, 조합이 90개면 1등이라도
q = 0.0025 × 90 ≈ **0.22**. 즉 **어떤 데이터로도 진입 신호가 나올 수 없는 상태**였습니다.

잡음에 안전했던 게 아니라 아예 잠겨 있었던 것이고, 무작위 데이터 시험은 전부
통과했기 때문에 티가 나지 않았습니다.

→ 이 귀무분포는 **오프셋 하나로만 결정**되므로 가짓수가 유한합니다. 표본추출할
이유가 없어서 **전수로 계산**하도록 바꿨습니다. 해상도가 봉 개수분의 1이 되면서
바닥이 사라졌고, 검출이 **0/10 → 10/10**이 됐습니다.

## 왜 180까지인가

더 늘려도 얻는 게 없고, 오히려 오해를 부릅니다. 1분봉 43,200개에서 질의 위치
30곳을 훑어 재보면:

| 길이 | 표본 20개 이상 나온 비율 | 표본 중앙값 |
|---|---|---|
| 5 | 97% | 60 |
| 20 | 57% | 34 |
| 60 | 27% | 1 |
| 120 | 23% | 2 |
| **180** | **20%** | **0** |
| 240 | 10% | 0 |
| 300 | 10% | 1 |
| 400 | 3% | 0 |

180에서 이미 다섯 번에 한 번만 표본이 찹니다. 240 이상은 열 번에 한 번,
400은 서른 번에 한 번입니다. 겹치지 않게 놓을 수 있는 최대 개수 자체가
줄어들기 때문입니다 (길이 600이면 1분봉 30일치에 최대 72개, 5분봉이면 14개라
표본 20개가 **원천적으로 불가능**합니다).

### 더 중요한 이유: 긴 창에서 표본이 나오면 그건 대개 직선입니다

긴 모양이 과거에 자주 반복될 리 없습니다. 그런데도 표본이 넉넉히 나온다면
모양이 단순해서입니다. 질의 위치 40곳의 직선성(직선 적합 R²) 중앙값:

| 길이 | 표본 20개 이상일 때 | 표본이 적을 때 |
|---|---|---|
| 60 | 0.72 | 0.25 |
| 120 | 0.72 | 0.38 |
| 180 | 0.80 | 0.40 |
| 240 | 0.83 | 0.22 |
| 300 | **0.88** | 0.22 |

길이 300에서 표본이 20개 넘게 나오면 그 '모양'은 88%가 직선으로 설명됩니다.
즉 "특이한 모양이 반복됐다"가 아니라 **"같은 방향으로 추세 중"**을 센 겁니다.

막지는 않습니다 — 추세를 타는 것도 근거는 근거입니다. 대신 **직선성을 같이
보여주고**, 0.75를 넘으면 표에 `~`를 붙이고 판정문에도 명시합니다. 사용자가
"직전 180개 모양이 과거에 25번 있었다"로 오해하지 않도록.

## 셈할 때 지키는 규칙

- **미래를 안 본다.** 후보 구간은 질의 구간이 시작하기 *전에* 끝나야 하고, 결과를
  관측할 h봉까지도 질의 구간 시작 전에 끝나야 합니다.
- **겹치면 안 센다.** 한 칸씩 밀린 구간들은 사실상 같은 구간입니다. 다 세면
  표본 30개가 실제로는 1개인데 30개인 척하게 됩니다.
- **끊긴 구간은 버린다.** 업비트는 거래가 없는 분의 봉을 주지 않습니다. 그 자리를
  이어 붙이면 실제로는 떨어진 두 시점이 연속된 모양으로 보입니다.
- **평평한 구간은 버린다.** 안 움직인 창끼리는 거리가 0이라 전부 '완벽한 매치'가
  됩니다.
- **보합은 실패로 센다.** 분모에 남깁니다. 안 그러면 승률이 부풀려집니다.

각각에 대응하는 시험이 `tests/test_scan.py`에 있습니다.

## 구조

```
patternscan/
  models.py     봉·시계열 자료구조, 볼 조합의 정의
  shape.py      '같은 모양'의 정의 — 정규화와 거리
  scan.py       과거에서 찾기 + 직후 결과 집계 + 순열검정
  stats.py      다중비교 보정, 신뢰구간, 최종 판정
  upbit.py      공개 시세 API (인증 없음)
  data.py       CSV 캐시
  report.py     터미널 출력
  search.py     빠른 모양 찾기 (결과는 전수 계산과 동일)
  validate.py   과거 여러 시점으로 돌아가 적중률 측정
  cli.py        명령줄
  webui/        로컬 화면 (분석 전용)
```

읽는 순서를 하나만 고른다면 `shape.py` → `scan.py` → `stats.py`입니다.
'같은 모양'의 정의에서 시작해 판정까지 이어집니다.

## 개발

```bash
pip install -e ".[dev]"
python -m pytest -q          # 120개 시험, 전부 오프라인
python -m ruff check patternscan tests
```

시험은 네트워크를 타지 않습니다. 업비트 장애나 레이트 리밋에 CI가 흔들리면
안 되기 때문입니다.
